# Releasing FreeBeams

How a release is built, locally and in CI, what needs credentials, and what is still unverified. Everything
below runs the same scripts in `bin/`; the GitHub Actions workflows only call them.

## The version

`config/version` in `graphics/project.godot` is the single source of truth.

- `bin/version` prints it; `bin/version --check vX.Y.Z` fails unless the tag matches (the release workflow runs it).
- The Godot exports fall back to it: the macOS and Windows presets leave their own version fields empty on purpose,
  so `CFBundleShortVersionString`/`CFBundleVersion` and the Windows file/product versions come from the same place.
- The app logs it at startup: `[freebeams] FreeBeams 0.1.0 (Godot 4.7.2-stable (official))`
  (`internal/app/version.go`, read from `ProjectSettings`; `app.Version()` is available for an About box or the title).
- The artifacts carry it: `FreeBeams-0.1.0-macOS.dmg`, `FreeBeams-0.1.0-windows-amd64.zip`,
  `FreeBeams-0.1.0-Setup.exe`, `FreeBeams-0.1.0-linux-amd64.tar.xz`, `FreeBeams-0.1.0-x86_64.AppImage`.

To bump: edit `config/version`, commit, tag `vX.Y.Z`.

## Icon

`graphics/icon.svg` is the master artwork (our own: an indigo tile, a projector beam and a lyric slide).
`packaging/icons/make-icons.sh` (macOS: QuickLook + iconutil + Pillow) regenerates the committed derivatives
`graphics/icon.png` (Linux, 512 px), `graphics/icon.ico` (Windows) and `graphics/FreeBeams.icns` (macOS).
`project.godot` points `config/icon`, `config/macos_native_icon` and `config/windows_native_icon` at them, and the
export presets use the `.icns`/`.ico`.

## Licence and notices

FreeBeams is MIT (`LICENSE`, Copyright (c) 2026 Devsecway). `THIRD-PARTY-NOTICES.txt` lists what the packages carry
besides our code (Godot and its `COPYRIGHT.txt`, graphics.gd, every linked Go module with its licence text, SQLite,
SCOWL, FFmpeg, zlib and winpthreads on Windows, the public-domain Bibles); `packaging/notices/make-notices.sh`
regenerates it from `go list -deps`, the Godot source at the pinned tag and `packaging/notices/` (`--check` tells
whether it is current; rerun it after a `go.mod` or Godot bump). Both files ship as `LICENSE.txt` and
`THIRD-PARTY-NOTICES.txt` in every package: `FreeBeams.app/Contents/Resources/`, next to `FreeBeams.exe` (zip and
installer; the Start menu has a "FreeBeams Licence" entry), and in the Linux tarball and AppImage (`usr/bin`).
Help ▸ About names the licence (`core.AboutText`). The installer shows `LICENSE` as its licence page and the DMG
shows it as its licence agreement.

## Artwork

`packaging/branding/make-art.py` (`python3 -I`, Pillow + numpy, macOS for `tiffutil`/`iconutil`) draws the
installer and file-type art from `graphics/icon.png` and the brand palette, all committed: the DMG background
(`packaging/macos/dmg-background.tiff`, 660×400 @1x/@2x, an indigo header with the instruction, the icons on a light
body because Finder draws their labels in black, an arrow between the two icon slots), the document icons for
schedules and Bible packages (`packaging/macos/{schedule,bible}.icns`, `packaging/windows/{schedule,bible}.ico`,
`packaging/linux/icons/hicolor/*/mimetypes/`), the Inno Setup wizard images at 100–200 % DPI
(`packaging/windows/wizard-{large,small}-*.bmp`) and the Linux app icons at 16–512 px plus the SVG.

## The engine template (smaller packages)

Every release export uses FreeBeams' own Godot export template instead of the stock one. `bin/build-engine
macos|windows|linux` builds it from the Godot source at the pinned tag (`GODOT_VERSION`/`GODOT_COMMIT`, the
version gd exports with), with `packaging/engine/custom.py`:

- `optimize=size`, `lto=full`, `production=yes`;
- `build_profile=packaging/engine/freebeams.build`: the 552 of 1078 engine classes the project does not use. It is
  generated by `go run packaging/engine/profile.go <godot source> packaging/engine/freebeams.build`, a port of
  graphics.gd's own `engine/strip_unused_classes` logic: a class stays when the Go code links its
  `graphics.gd/classdb` package (graphics.gd looks up every linked class's method binds at startup, so a missing
  one is a Godot `ERROR`), when its name appears in the project's files or Go sources, when
  `packaging/engine/keep.txt` names it (Theora, Vorbis, the imported icon texture, `ArrayMesh` because Godot binds
  some `Mesh` methods there) or when a kept class needs it. **Regenerate it after a change that uses a new engine
  class**, then run the smoke test against an export (below): a missing class shows as `null bind` / `ERROR:
  Parameter "mb" is null` in the log;
- unused modules off (XR, glTF/FBX, CSG, GridMap, navigation, 3D physics (`physics/3d/physics_engine="Dummy"` in
  `project.godot`), networking, GDScript, Mono, MP3, the fallback text server, ...), SDL (game controllers) off;
- drivers: macOS arm64 Metal + OpenGL, macOS x86_64 Vulkan through a static MoltenVK (`MOLTENVK_VERSION`, from
  KhronosGroup's release) + OpenGL, both lipo'd into a `macos.zip` laid out like Godot's; Windows x86_64 (MSVC)
  Vulkan + OpenGL (no D3D12 or ANGLE fallbacks: a machine without Vulkan falls back to native OpenGL); Linux
  x86_64 Vulkan + OpenGL, X11 + Wayland. AccessKit (screen readers) stays, as in the official templates.

The template lands in `releases/engine/` and is cached under `$ENGINE_CACHE` (default `~/.cache/freebeams/engine`)
keyed on the script, `custom.py` and the profile; the source checkout is kept there too. `bin/build-engine --use
<platform>` points the platform's preset `custom_template/release` at it and `--restore` puts
`graphics/export_presets.cfg` back: the release scripts do both around `gd build`, so the committed preset (and a
plain `GOOS=… bin/gd build`) keep the stock template. `STOCK_ENGINE=1` makes `bin/release-dmg`, `bin/build-windows`
and `bin/build-linux` use the stock template. Needs scons (`pipx install scons`) and the platform's C++ toolchain
(Xcode CLT; Visual Studio 2022; gcc + `libwayland-bin`). Build times: about 1 min per slice on an M3 Max, 8–9 min
per macOS slice on `macos-15`, 12 min on `ubuntu-22.04`, 22 min on `windows-latest`.

To check an export end to end: `SMOKE_APP=releases/darwin/universal/FreeBeams.app/Contents/MacOS/FreeBeams
test/smoke.sh` runs the whole smoke test against the exported app instead of `gd run`.

The Go library is already built with `-ldflags=-s -w` by `gd build`; UPX is deliberately not used (antivirus false
positives).

## macOS

```bash
bin/release-dmg             # the app with the custom template, then releases/FreeBeams-<v>-macOS.dmg
bin/release-dmg --app-only  # the finished app only (bin/sign-notarize uses it); SKIP_BUILD=1 repackages
```

After the export `bin/release-dmg` copies `LICENSE.txt`, `THIRD-PARTY-NOTICES.txt` and the document icons into
`Contents/Resources` and signs the bundle ad hoc again (the added files break the export's seal), then checks
`Info.plist`: the version, `NSHumanReadableCopyright` ("Copyright © 2026 Devsecway", from the preset's
`application/copyright`) and the file types. Those come from the preset's `application/additional_plist_content`:
`CFBundleDocumentTypes` (FreeBeams Schedule, role Editor, and FreeBeams Bible Package, role Viewer, both
`LSHandlerRank Owner` with their own icons) and `UTExportedTypeDeclarations` (`com.devsecway.freebeams.schedule` for
`.fbs`/`.fws`, `com.devsecway.freebeams.bible` for `.fbbible`). The DMG is made by
[dmgbuild](https://github.com/dmgbuild/dmgbuild) (`packaging/macos/dmg-settings.py`; installed into
`~/.cache/freebeams/dmgbuild-1.6.7` when it is not on PATH), which writes the Finder layout itself, so no
AppleScript or Finder automation permission is involved: a 660×400 window with the background, 112 px icons at
fixed positions, no toolbar or sidebar, the app icon as the volume icon, the MIT licence as the licence agreement
(`hdiutil udifrez`, still present on macOS 26), lzma-compressed (`ULMO`, macOS 10.15+; the app needs 12+ for Go).

`gd build` compiles `darwin_arm64.dylib` and `darwin_amd64.dylib`, lipo's them into `darwin_universal.dylib`, and
runs Godot's headless export of the `macOS` preset (ad-hoc signed by Godot). The first run downloads the macOS
export template (124 MB) into `~/Library/Application Support/Godot/export_templates/4.7.2.stable/`.

To check the exported app without a GUI test:

```bash
FREEBEAMS_LIBRARY=$(mktemp) FREEBEAMS_CONTROL_KEY=testkey \
  releases/darwin/universal/FreeBeams.app/Contents/MacOS/FreeBeams &
# stdout prints "Control server: http://127.0.0.1:<port>"
curl -H 'Authorization: Bearer testkey' http://127.0.0.1:<port>/state
curl -X POST -H 'Authorization: Bearer testkey' -d '{}' http://127.0.0.1:<port>/action/quit
```

### Signing and notarizing (needs credentials)

`bin/sign-notarize` deep-signs every Mach-O in the bundle with the hardened runtime and
`packaging/macos/entitlements.plist`, packages the DMG through `bin/release-dmg`, signs it, submits it to Apple's
notary service, staples the ticket to the DMG and the app, and validates. It needs:

| Credential | Local | CI (repository secrets) |
|---|---|---|
| Developer ID Application certificate | in the login keychain, named by `SIGN_IDENTITY` | `MACOS_CERT_P12_BASE64`, `MACOS_CERT_PASSWORD` (imported into a throwaway keychain) |
| Notary access | `NOTARY_PROFILE` from `xcrun notarytool store-credentials` | `APPLE_API_KEY_P8_BASE64`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER_ID` (App Store Connect API key) |

```bash
SIGN_IDENTITY="Developer ID Application: Name (TEAMID)" NOTARY_PROFILE=freebeams-notary bin/sign-notarize
SKIP_NOTARIZE=1 ...   # sign only; SKIP_BUILD=1 reuses the built app
```

Without credentials the script stops before touching the build, with a message naming what is missing. The
release workflow runs it only when the secrets are set and otherwise uploads an unsigned DMG with a warning.

## Windows

```bash
bin/build-windows     # releases/windows/amd64/, releases/FreeBeams-<v>-windows-amd64.zip, releases/FreeBeams-<v>-Setup.exe
```

The installer (`packaging/windows/freebeams.iss`, Inno Setup 6): the MIT licence page, the branded wizard images
and setup icon, publisher Devsecway with the project, support and release URLs and a version resource, a per-user
install without admin rights by default (an administrator may pick all users), a Start-menu shortcut (plus one
for the licence), an optional desktop shortcut, lzma2/ultra64 solid compression. File types, registered under
`HKA\Software\Classes` (the user's or the machine's, as installed): ProgIDs `FreeBeams.Schedule` (`.fbs`, legacy
`.fws`) and `FreeBeams.BiblePackage` (`.fbbible`) with their icons and an open command `"FreeBeams.exe" "%1"`; the
"File types" task (on by default) makes FreeBeams their default handler, and they are always in "Open with". The
uninstaller removes the program, the registrations and `%LOCALAPPDATA%\FreeBeams` (caches), and asks (default No)
before removing the library in `%APPDATA%\FreeBeams`; `Documents\FreeBeams` is never touched. The zip uses
`zip -9`.

Native build on Windows under MSYS2 UCRT64 (`pacman -S mingw-w64-ucrt-x86_64-gcc`), with Go on PATH:
`MSYSTEM=UCRT64 /c/msys64/usr/bin/bash -l bin/build-windows`. On a fresh machine `bin/setup-windows.ps1` (an
elevated PowerShell) installs Go, Git, MSYS2 with gcc and zip, and Inno Setup through winget, then runs this script. It runs `GOOS=windows bin/gd build` (gcc builds
`windows_amd64.dll`, Godot exports the `Windows x86_64` preset), copies the DLL beside `FreeBeams.exe`, bundles any
`lib*.dll` the DLL still needs, adds the LGPL `ffmpeg.exe` / `ffprobe.exe` (`bin/build-ffmpeg`, see below), brands the exe with `rcedit` (icon, version resource: Godot only does this itself when
rcedit is configured in its editor settings), zips the folder, and builds the installer from
`packaging/windows/freebeams.iss` with Inno Setup (`ISCC`). `SIGNTOOL_CMD="signtool sign ..."` is the Authenticode
hook; it runs on every PE file when set. Cross-building from macOS or Linux needs `zig` on PATH (gd uses `zig cc`)
and produces the zip only.

## Linux

```bash
bin/build-linux       # releases/linux/<arch>/, releases/FreeBeams-<v>-linux-<arch>.tar.xz, releases/FreeBeams-<v>-x86_64.AppImage
```

Desktop integration (`packaging/linux/`): `com.devsecway.freebeams.desktop` (`MimeType`, `%F`,
`StartupWMClass=FreeBeams`, which is Godot's X11 class and Wayland app id for the project name),
`freebeams-mime.xml` (shared-mime-info: `application/x-freebeams-schedule` for `*.fbs`/`*.fws`,
`application/x-freebeams-bible` for `*.fbbible`), `com.devsecway.freebeams.metainfo.xml` (AppStream, `project_license`
MIT, the version and date filled in), and the hicolor icons. `bin/build-linux` validates the desktop entry and the
AppStream file (`desktop-file-validate`, `appstreamcli validate --no-net`) when the tools are there (CI installs
them). The tarball is `tar.xz` (`xz -9e`): the bundle plus `install.sh` (`./install.sh` into `~/.local`, `sudo
./install.sh --system` into `/usr/local`, `--prefix`, `--uninstall`; it installs the program into
`<prefix>/lib/freebeams`, a `freebeams` command, the menu entry, MIME types, icons and metainfo, and refreshes the
caches), `README.txt` and `share/`. The AppImage carries the same `usr/share` tree and is squashed with zstd at level
22 and 1 MiB blocks.

Linux only, natively (GOARCH must be the host's). Build on an old distro (CI: `ubuntu-22.04`) so the glibc floor
stays low. The tar.gz holds the binary, `linux_<arch>.so`, the LGPL `ffmpeg` / `ffprobe` (below), a launcher (`freebeams.sh`), the icon and the
`.desktop` file; the AppImage is assembled from `packaging/linux/` (`AppRun` preloads the `.so` for the aarch64
static-TLS issue) with `appimagetool`, downloaded into `~/.cache/freebeams/` when missing (`APPIMAGETOOL=` to
point at one, `NO_APPIMAGE=1` to skip).

## Bundled ffmpeg (Windows and Linux)

The Windows zip and installer, the Linux tar.gz and the AppImage (`usr/bin`) carry `ffmpeg` / `ffprobe` next to the
app, with `FFMPEG-LICENSE.txt` (the LGPL v2.1 text from the source tarball) and `FFMPEG-NOTICE.txt`
(`packaging/ffmpeg/NOTICE.txt` plus the version, source URL, SHA-256 and configure line). The app finds them there
first (`media.Locate`; then PATH) and plays every video and audio file through them ([MEDIA.md](MEDIA.md) "the
ffmpeg player"). macOS ships none: AVFoundation plays, and poster frames use an ffmpeg on PATH when there is one.

`bin/build-ffmpeg` builds them from source:

- the pinned release `FFMPEG_VERSION=8.1.3` from `https://ffmpeg.org/releases/`, checked against
  `FFMPEG_SHA256` before anything is extracted (a mismatch stops the build);
- configured without `--enable-gpl` / `--enable-nonfree` and with `--disable-autodetect --enable-zlib` (no other
  external library can slip in from the build machine); the FFmpeg libraries are **shared** and sit next to the two
  programs (`avcodec-62.dll`, ... on Windows with `zlib1.dll` and `libwinpthread-1.dll` from the toolchain, which the
  script finds with `objdump` and copies; `libavcodec.so.62`, ... on Linux, each given an `$ORIGIN` rpath with
  `patchelf`; `@loader_path` on macOS), so ffmpeg and ffprobe share one libavcodec instead of carrying one each
  (half the size of the former static pair); no ffplay, docs, network or devices; every native decoder, demuxer,
  parser and filter,
  but only the encoders / muxers the app runs (`mjpeg`, `png`, `rawvideo`, `pcm_f32le`, `pcm_s16le`,
  `wrapped_avframe`; `image2`, `image2pipe`, `mjpeg`, `rawvideo`, `pcm_f32le`, `pcm_s16le`, `wav`, `null`);
- the script fails unless configure says `License: LGPL version 2.1 or later` and the built ffmpeg lists the
  `rawvideo` / `f32le` / `image2` muxers and the `mjpeg` / `rawvideo` / `pcm_f32le` encoders (configure silently
  ignores an unknown component name: `f32le` is `pcm_f32le` there);
- it installs into `$FFMPEG_CACHE` (default `~/.cache/freebeams`)`/ffmpeg-<version>-<os>-<arch>-shared/` once;
  `bin/build-ffmpeg --prefix` prints that folder. Needs make, nasm (x86) and zlib: `apt install nasm
  zlib1g-dev patchelf`, MSYS2 `make diffutils nasm mingw-w64-ucrt-x86_64-{pkgconf,zlib}` (`bin/setup-windows.ps1`
  installs them). `NO_FFMPEG=1 bin/build-windows` / `bin/build-linux` skip the bundle; a Windows cross build from
  macOS / Linux ships none.

To bump: set `FFMPEG_VERSION`, download the tarball, put its `shasum -a 256` into `FFMPEG_SHA256`. The release
workflow caches the build keyed on the script and runs the player tests against the bundled binaries
(`FREEBEAMS_FFMPEG_DIR=releases/<os>/amd64 go test ./internal/media/ffplayer/`, with the distribution's ffmpeg
making the test clips).

Licence obligations: the LGPL text and the notice travel with the binaries; the notice names the exact source
tarball and configure line, and the repository holds the build script. The binaries run as separate programs
(no linking into FreeBeams), and users may replace them.

## CI

- `.github/workflows/ci.yml`: on push to `main` and on pull requests: `gofmt -l`, `go build`, `go vet`, `go test`
  on `macos-15` (the EasyWorship-data tests skip there), plus `shellcheck` over the scripts on Ubuntu, plus the
  pure-Go media packages (`internal/media/...` with the ffmpeg player, `internal/sysproc`) on `windows-latest`
  and `ubuntu-latest` with ffmpeg installed (choco / apt; `FREEBEAMS_REQUIRE_FFMPEG=1` makes a missing ffmpeg
  fail instead of skip), so the process and pipe code runs for real on Windows.
- `.github/workflows/release.yml`: on a `v*` tag (or by hand, for a dry run without a release): checks the tag
  against `bin/version`, then builds macOS (`macos-15`), Windows (`windows-latest`, MSYS2) and Linux (`ubuntu-22.04`)
  natively, uploads the artifacts, and for a tag creates a **draft** GitHub release with the artifacts and
  `SHA256SUMS.txt` for a maintainer to publish. Godot and the export templates are cached under `$GDPATH/bin` and the
  per-OS template directory, keyed on `go.mod`; the custom engine template is built in its own step before the
  package (`bin/build-engine <platform>`, MSVC from Git Bash on Windows) and cached with `actions/cache/restore` +
  `save` right after it is built (keyed on `bin/build-engine` and `packaging/engine/`), so a later failure does
  not lose it. `GOTOOLCHAIN` is set to the installed Go version because
  `actions/setup-go` pins `GOTOOLCHAIN=local`, which gd reads as "download nothing".

Cutting a release:

```bash
# 1. bump config/version in graphics/project.godot, commit
# 2. tag and push
git tag v0.1.0 && git push origin v0.1.0
# 3. wait for the Release workflow, review the draft at github.com/<org>/freebeams/releases, publish
```

## Sizes (v0.2.0 as released → this packaging, same app code)

| Package | Before | After | What changed |
|---|---|---|---|
| `FreeBeams-<v>-macOS.dmg` | 94.5 MB | 48.5 MB | engine 167 → 77 MB (universal), ULMO |
| `FreeBeams-<v>-Setup.exe` | 58.5 MB | 33.2 MB | engine 110 → 40 MB, shared FFmpeg 54 → 28 MB, lzma2/ultra64 |
| `FreeBeams-<v>-windows-amd64.zip` | 77.9 MB | 43.2 MB | the same, `zip -9` |
| `FreeBeams-<v>-x86_64.AppImage` | 60.4 MB | 36.6 MB | engine 75 → 40 MB, shared FFmpeg 44 → 23 MB, zstd 22 |
| `FreeBeams-<v>-linux-amd64.tar.gz` → `.tar.xz` | 64.9 MB | 31.5 MB | the same, `xz -9e` |

The rest is the Go library (`darwin_universal.dylib` 75 MB, `windows_amd64.dll` 39 MB, `linux_amd64.so` 42 MB:
the app, SQLite and the three bundled Bibles), which `gd build` already strips.

## Not verified here (known gaps)

- **Signing and notarization**: no Developer ID certificate or notary credentials on this machine. The app stays
  unsigned (ad hoc). `bin/sign-notarize` now builds the app with `bin/release-dmg --app-only` before signing.
- **Running the Windows installer and the AppImage**: built and inspected in CI, not installed on a Windows or Linux
  desktop (the file associations, the uninstaller's library question, `install.sh`, the AppImage's first start).
- **The engine on other machines**: the custom templates ran the full smoke test on Apple silicon only. The Intel
  slice (Vulkan through the static MoltenVK) and the Windows / Linux templates were built and exported in CI but not
  started on a desktop with a GPU.
- **A second launch with a file while the app runs** hands the file over through the instance file next to the
  library (`control.Forward`, unit-tested); on macOS a document opened while the app runs makes Godot start a new
  instance, which then hands over and quits. Not tried by hand from Finder or Explorer.
